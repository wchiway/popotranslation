# Windows 输入与兼容性

查证日期：2026-10-28。

目前的 Windows 输入模块仅在快捷键触发后尝试读取普通可编辑控件。UI Automation 在独立 MTA 线程运行：仅接受 `Edit` 类型；密码属性未知或为真时拒绝，控件必须启用。读取选区需要 TextPattern；读取整个控件可以使用 TextPattern 或 ValuePattern。两者同时存在时全文必须一致，且仅允许一个选区、前台窗口和进程必须对应。读取两次并比较窗口、进程实例、控件运行时标识、全文和选区，任何不一致都拒绝取文。仅提供 TextPattern 的多行/富文本控件可以读取，但通常无法自动写回，结果会转手动复制。部分应用、跨进程嵌入控件、文档编辑器和未提供这些模式的控件仍会被拒绝。

整框回填仅尝试标准 Win32 `Edit` 单行控件：目标必须在前台且保有系统输入焦点，非密码、可写，并且输入线程使用非 IME 英语键盘布局；还要通过任务有效性门禁，重新核对进程实例、控件、原文和选区。快捷键触发时会记录当时的前台窗口，读取前后都核对该窗口，避免界面线程排队期间切窗后误读其他应用。成功调用 ValuePattern.SetValue 后，再观察该控件的值，读回一致才标记已应用；写入抛错或无法读回标记为提交结果无法确认。选区、非标准控件、多行译文或无法验证时交由用户手动应用。没有实现剪贴板兼容取文，也不会自动发送消息。文本与选区快照只在内存中保留，调用方应避免记录它们。

回填前检查与写入不是原子操作：目标应用或用户仍可能在检查后修改内容，UIA 控件也可能报告不准确数据。限制英语非 IME 布局可以减少组合输入风险，但无法证明没有 TSF 组合或第三方输入法；未验证的输入环境应采用手动应用。对已提交但未确认的结果应先检查目标，避免重复覆盖。

UI Automation 同步调用可能被目标应用阻塞。独立线程避免阻塞 UI；每次只接受一个操作。取文取消只停止等待，不能终止已经开始的 COM 调用；回填一旦排队则等待操作完成，以免取消后误以为未写入。若调用永久阻塞，后续取文会返回忙碌，直至进程退出；当前没有独立的可终止辅助进程，回填任务及任务状态门禁也可能因此等待。高权限窗口、受保护桌面、中文输入法组合中的内容和目标应用提供不准确 UIA 属性的情况均未验证，不应承诺支持。

托盘使用隐藏顶层消息窗口来接收 `TaskbarCreated`，请求重新添加图标；菜单和快捷键事件在该窗口的专用线程上触发，界面调用方需自行切换到 UI 线程。图标句柄由调用方提供并保证其有效，退出时先释放托盘和快捷键，再释放消息窗口。结果通知仅显示通用提示，不包含原文或译文；系统可能不显示通知，必须提供其他打开结果的入口。快捷键使用系统无重复注册；成对更新先注册新增组合，失败保留旧组合，交换动作时复用原注册。极少数系统注销失败可能留下暂时占用的热键，服务会在退出时重试释放。托盘通知、Explorer 重启恢复与真实跨应用快捷键尚未人工验收。

| 目标或场景 | 当前验证状态 |
| --- | --- |
| 快照身份、文本和选区一致性 | 使用脱敏内存数据自动检查 |
| 快捷键冲突及释放 | 使用模拟原生注册边界自动检查 |
| 记事本、浏览器、Electron、微信或 QQ | 未测试 |
| 中文输入法未上屏、受保护和管理员窗口 | 未测试 |
| 标准单行 Edit 整框回填 | 已有保守实现；真实控件尚未验收 |
| 选区回填、撤销栈和富文本 | 未实现，手动应用 |
| Explorer 重启、托盘菜单及系统快捷键冲突 | 未人工测试 |
