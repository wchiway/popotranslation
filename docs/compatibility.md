# Windows 输入与兼容性

查证日期：2026-10-28。

## 读取路径

程序在快捷键触发后先记录前台窗口，再尝试 UI Automation：

- `Edit` 控件支持选区、整框和多行文本；`Document` 控件支持选区读取。
- 密码属性未知或为真、控件禁用、只读整框读取会被拒绝。
- 读取两次并比较窗口、进程实例、控件运行时标识、全文和选区；任何不一致都拒绝取文。
- 仅提供 TextPattern 的多行/富文本控件通常无法直接写回，会用剪贴板兼容粘贴或转为手动复制。

如果前台是 QQ、微信（Weixin/WeChatAppEx）、Discord 或 Telegram，且 UI Automation 无法取得可编辑文本，则使用剪贴板兼容路径：

- 读取选区时发送 Ctrl+C；读取整框时发送 Ctrl+A、Ctrl+C。
- 仅在剪贴板原内容为文本或空时开始；原内容会尽量恢复。原内容为图片或文件时不再中止，而是保存和恢复整个 DataObject；恢复失败可能只留下译文。
- 终端不执行整框读取，也不自动写回；请先选中文本，使用选区备用快捷键，通过 UIA 或 Ctrl+Shift+C 读取后手动复制译文。

## 写入路径

- UI Automation 的 `Edit` 控件如果提供可写 ValuePattern，可整框设置，支持多行；设置后读回一致才报告“已应用”。
- 选区、部分多行/富文本控件，以及社交软件的剪贴板快照，使用剪贴板粘贴：整框会再次 Ctrl+A，选区直接 Ctrl+V。
- 剪贴板快照会先重新复制并比较原文/选区，目标窗口、进程或内容变化时拒绝写入。
- 终端、管理员窗口、密码框、无法验证的目标一律转手动应用。

## 已知边界

跨进程检查与写入不是原子事务。目标应用或用户仍可能在检查后继续输入，UIA 控件也可能报告不准确数据。剪贴板粘贴无法获得目标应用的完成确认，因此结果标记为“已提交但无法确认”；自动恢复剪贴板与目标读取剪贴板之间存在时间竞态。三次空格会拦截第三次空格，前两次空格会从翻译源文本中去除；输入法组合中的内容、超长文本和部分自绘控件未验证。社交软件整框读取会发送 Ctrl+A，若翻译失败，目标输入框可能暂时保持全选状态；终端不执行整框读取。

目前自动化检查覆盖快照身份、文本/选区变化、热键序列、目标应用分类和剪贴板服务的基础路径；真实 QQ、微信、Discord、Telegram、Windows Terminal 及不同输入法状态仍需人工验收。
